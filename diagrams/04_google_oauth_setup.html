Procedura Setup Credenziali Google Calendar

Configurazione OAuth 2.0 per l'integrazione google-calendar-mcp in LibreChat

📅 Maggio 2026 🏗️ Progetto: LibreChat + agents-gateway 👤 dome.zurlo@gmail.com

1. Prerequisiti

RequisitoDettaglio
Account GoogleAccount da usare per il calendario (dome.zurlo@gmail.com)
Google Cloud ProjectProgetto con le API di Google Calendar abilitate
DockerDocker Desktop attivo con i container LibreChat
File google_token.jsonCreato nella root del progetto (inizialmente {})

2. Creazione del Client OAuth 2.0 in Google Cloud Console

1Abilita la Google Calendar API

  1. Vai su console.cloud.google.com
  2. Seleziona (o crea) il progetto Calendar
  3. Menu → API e servizi → Libreria
  4. Cerca Google Calendar API → Abilita

2Configura la schermata di consenso OAuth

  1. Menu → API e servizi → Schermata consenso OAuth
  2. Tipo utente: Esterno
  3. Compila nome app, email supporto, email sviluppatore
  4. Scope: aggiungi https://www.googleapis.com/auth/calendar
  5. Lascia lo stato in Testing (non serve pubblicare)
⚠️ In modalità Testing solo gli utenti aggiunti come "Test users" possono completare il flusso OAuth. Vai su Pubblico → Test users → + ADD USERS e aggiungi l'account Google che userà il calendario.

3Crea le credenziali OAuth 2.0

  1. Menu → API e servizi → Credenziali → + Crea credenziali → ID client OAuth 2.0
  2. Tipo applicazione: Applicazione web (non Desktop)
  3. Nome: es. google-calendar-mcp
  4. Aggiungi URI di reindirizzamento autorizzato: 
    http://localhost:3000/auth/callback
  5. Salva → copia Client ID e Client secret
ℹ️ Il tipo Desktop non supporta redirect URI HTTP arbitrari — usare sempre Applicazione web per integrazioni server-side.

3. Configurazione del progetto LibreChat

4Variabili d'ambiente in .env

Aggiungi le seguenti variabili al file .env nella root del progetto:

# Google Calendar OAuth 2.0
GOOGLE_CLIENT_ID=689916846597-q3cgddj5nqk8bdvua66g2huucglstncv.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

5File google_token.json

Crea il file nella root del progetto con contenuto vuoto:

{}

Questo file verrà popolato automaticamente dopo il flusso OAuth e persiste tra i restart del container grazie al bind mount in docker-compose.override.yml:

volumes:
  - ./google_token.json:/app/token.json

4. Avvio dei container

6Avvia lo stack completo

docker compose -f docker-compose.yml -f docker-compose.override.yml up -d

Il container google-calendar-mcp sarà raggiungibile su http://localhost:3000.

ℹ️ Il container usa npx -y google-calendar-mcp — scarica automaticamente il pacchetto npm google-calendar-mcp v1.0.9 al primo avvio.

5. Completamento del flusso OAuth (una tantum)

7Apri l'URL di autorizzazione nel browser

Costruisci l'URL manualmente (il server MCP non espone un endpoint /auth/url HTTP) e aprilo nel browser:

https://accounts.google.com/o/oauth2/v2/auth
  ?client_id=TUO_CLIENT_ID
  &redirect_uri=http%3A%2F%2Flocalhost%3A3000%2Fauth%2Fcallback
  &response_type=code
  &scope=https%3A%2F%2Fwww.googleapis.com%2Fauth%2Fcalendar
  &access_type=offline
  &prompt=consent
⚠️ access_type=offline è necessario per ottenere il refresh_token, indispensabile per rinnovare l'accesso senza ripetere il flusso OAuth.
prompt=consent forza la richiesta del refresh_token anche se l'utente ha già autorizzato in precedenza.

8Autorizza l'accesso su Google

  1. Google mostra la schermata di consenso
  2. Seleziona l'account dome.zurlo@gmail.com
  3. Clicca Continua → Consenti
  4. Il browser viene reindirizzato su http://localhost:3000/auth/callback?code=...
  5. Il server MCP intercetta la callback, scambia il code con i token e li scrive in /app/token.json

9Verifica il token salvato

Il file google_token.json nella root del progetto deve essere popolato con una struttura simile:

{
  "access_token":  "ya29.a0AQvP...",
  "refresh_token": "1//03LGL8...",
  "scope":         "https://www.googleapis.com/auth/calendar",
  "token_type":    "Bearer",
  "expiry_date":   1780247110891
}
✅ Se il file è popolato il flusso OAuth è completato. Il refresh_token consente di rinnovare automaticamente l'accesso — non è necessario ripetere la procedura.

6. Come funziona il container google-calendar-mcp

EndpointMetodoDescrizione
/healthGETHealth check del server
/mcp/infoGETMetadati del server MCP
/auth/callbackGETCallback OAuth — riceve il code da Google
/auth/directPOSTAuth alternativa via cookie/credenziali
/mcp/calendarsGETLista calendari disponibili
/mcp/events/upcomingGETProssimi eventi (tutti i calendari)
/mcp/events/createPOSTCrea un evento
/mcp/events/updatePUTModifica un evento
/mcp/events/deleteDELETEElimina un evento
/mcp/events/detailGETDettaglio di un evento specifico
ℹ️ Tutte le route operative sono sotto il prefisso /mcp/. Il nome del pacchetto "MCP" è fuorviante: non espone il protocollo MCP/SSE — è una pura REST API con autenticazione OAuth 2.0.

7. Formato payload per la creazione eventi

Il body va inviato come { eventData: { ... } } — il payload NON è flat:

POST /mcp/events/create
Content-Type: application/json

{
  "eventData": {
    "calendarId":  "primary",
    "summary":     "Verifica Tecnica — Domenico Zurlo",
    "description": "Note opzionali",
    "start":       { "dateTime": "2026-06-01T09:00:00+02:00" },
    "end":         { "dateTime": "2026-06-01T10:00:00+02:00" }
  }
}

8. Rinnovo delle credenziali

Il refresh_token ha una durata di ~7 giorni in modalità Testing. Per rinnovarlo:

  1. Ripeti lo Step 7 con l'URL OAuth (il prompt=consent forza un nuovo consent)
  2. Il file google_token.json viene sovrascritto con i nuovi token
  3. Non è necessario riavviare i container
⚠️ Per eliminare la scadenza del refresh_token è necessario pubblicare l'app OAuth (passare da Testing a In produzione nella schermata consenso). Per uso interno/demo non è necessario.
